# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Toy Chest Arcade — a toddler-friendly browser arcade, self-contained, works offline, and installable as a PWA. There is no build system, package manager, or test suite; it's plain static HTML/CSS/JS.

## Running / testing changes

There is no build, lint, or test command. To verify a change:
- Open `index.html` directly in a browser, or serve the directory (e.g. `python3 -m http.server`) since service worker registration requires `http(s)://`, not `file://`.
- Manually exercise the launcher and each game (character picker, movement controls, win banner, sound toggle where present).
- Check DevTools → Application tab to confirm the service worker registers and offline reload works.

## Architecture

`index.html` is the entire app. It has two layers:

1. **Launcher shell** (top-level `<style>`/`<script>` at the start of the file): renders `#launcher` with game-picker cards (`#cardPip`, `#cardKpop`, `#cardTotoro`) and an `#gameView` containing a single `<iframe id="gameFrame">`.
2. **Games**, stored as raw HTML strings in the `GAME_SRC` object (`pip`, `kpop`, `totoro` keys, defined near the bottom of the file). Each value is a *complete* standalone HTML document (own `<style>` and `<script>`) for one game:
   - `pip` — "Pip and the Stars" (platformer, collect stars, switchable character)
   - `kpop` — "Rooftop Hunters" (platformer, collect notes, switchable character)
   - `totoro` — "Totoro's Rainy Climb" (climbing game with music)

`playGame(key)` sets `frame.srcdoc = GAME_SRC[key]` to load a game into the iframe; `goHome()` tears it down by clearing `srcdoc` and setting `frame.src = 'about:blank'` so the game's `requestAnimationFrame` loop and Web Audio context actually stop (they don't stop just from hiding the iframe).

Each game internally follows the same pattern: a `<canvas>` game loop (`update()` + `draw()` driven by `requestAnimationFrame`), on-screen touch buttons (`#bLeft`/`#bRight`/`#bJump` or similar) plus keyboard binding via a `bind(el, key)` helper, a character-picker overlay (`#pick`/`#cards`), a win `#banner`, and simple Web Audio beeps/tones (`blip()`/`tone()`) — no external asset files, no audio/image files loaded over the network.

Because each game is a self-contained string, editing one requires finding its `<!DOCTYPE html> ... </html>` block inside `GAME_SRC` (search for the game's key, e.g. `kpop:`) rather than editing a separate file.

## Other files

- `manifest.json` — PWA metadata (name, icons, standalone display).
- `service-worker.js` — cache-first offline caching for `index.html`, `manifest.json`, and the icons. **Bump `CACHE_NAME` whenever `index.html` changes**, or installed/tablet clients will keep serving the stale cached version indefinitely.
- `pwabuilder-sw.js` — a separate offline-fallback service worker generated by PWABuilder; it references a placeholder page (`ToDo-replace-this-name.html`) that doesn't exist in this repo and is not currently registered by `index.html` (only `service-worker.js` is). Leave as-is unless actually wiring up PWABuilder's offline-fallback flow.
- `icons/`, `images/` — app icons at various sizes for the manifest and Android packaging.
- `.well-known/assetlinks.json` — Digital Asset Links file for Android TWA verification, filled in after packaging with PWABuilder (package name + SHA-256 cert fingerprint).

## Deployment

Hosted via GitHub Pages (Settings → Pages → Deploy from branch → `main` → `/root`), served at `https://<username>.github.io/<repo-name>/`. To ship an Android/tablet build, the Pages URL is run through pwabuilder.com to produce a signed package, and the resulting fingerprint/package name go into `.well-known/assetlinks.json`.
